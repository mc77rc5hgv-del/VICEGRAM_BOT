# VOLNA Engine v1 — первый инкремент

Общее Rust-ядро политики соединения рядом с действующим `med-vpn/`.
Рабочая база: `claude/vpn-capabilities-vpfinv`. Hysteria2, Happ, Telegram-бот,
подписки и сервер пока работают по существующей схеме.

## Реализовано

- Строгие состояния подключения, деградации, подготовки резерва и миграции.
- AUTO/FAST scoring с проверкой диапазонов и отказом от NaN/Infinity.
- Ограниченное расписание конкурентных попыток с задержкой запуска.
- Выбор достаточно хорошего готового соединения либо лучшего на дедлайне.
- Резерв из независимого failure domain.
- EWMA потерь и гистерезис решения о подготовке резерва.
- Контракт адаптера транспорта; Hysteria2 сохранён как миграционный вариант.

Это библиотека политики, а не готовый VPN. Расписание не запускает сетевые попытки.
AWG, MASQUE, TCP/TLS и Hysteria2 пока перечислены как типы, без реализаций.
Пороговые значения начальные, требуют настройки на реальных измерениях.

## Следующий инкремент

1. Async runtime: параллельные диагностические и connect задачи, cancellation,
   общий дедлайн, лимит ресурсов, очистка проигравших сессий.
2. Первый реальный адаптер и интеграционный стенд с проходящими IP-пакетами.
   Выбрать и проверить версии существующих стеков; TCP/TLS — конкретный
   защищённый протокол, а не просто открытый TCP socket.
3. Подписанный manifest: ключи, canonical bytes, rollback protection, expiry,
   ограниченная offline grace policy и last-known-good. До проверки подписи
   удалённая конфигурация не становится доверенным источником маршрутов.
4. Android VpnService/JNI/TUN, защита DNS и трафика во время переключений.
5. Реальные AWG/MASQUE/TCP адаптеры, Edge registry и end-to-end health.
6. Минимальная добровольная телеметрия: агрегаты качества, сроки хранения,
   исключение URL, DNS-истории и содержимого трафика.

## Runtime contract

- `choose_ready` принимает только сессии с подтверждённой аутентификацией и
  end-to-end IP/DNS проверкой. Сам handshake этого не доказывает.
- Во время prewarm только активная сессия владеет маршрутом TUN; резерв
  не меняет системную маршрутизацию до атомарной активации.
- Результаты старых гонок после Stop или смены сети нужно игнорировать по
  generation ID. Idle не следует переводить в NoConnectivity.
- Timeout, отсутствие health samples и полная потеря активного пути
  требуют отдельного liveness deadline; loss monitor этого не обнаруживает.
- После подтверждённого переключения закрыть старую сессию, сбросить
  health monitor, применить cooldown. Смена exit может оборвать TCP-сессии.
- Недоступность всех VPN-маршрутов означает Failed; NoConnectivity относится
  к отсутствию физической сети.
- Сетевые пробы учитывать отдельно для каждой пары edge/transport и IP family.

## Проверка

```sh
cargo test --manifest-path volna-core/Cargo.toml
cargo clippy --manifest-path volna-core/Cargo.toml --all-targets -- -D warnings
```

Контрольная точка Engine v1: Android проходит реальные сценарии доступного UDP,
заблокированного UDP, отказа edge и смены Wi-Fi/LTE, выбирает рабочий маршрут
и восстанавливает передачу без утечек. Unit-тесты политики её не заменяют.
